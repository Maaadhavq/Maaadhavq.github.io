PAD Detection + Risk Copilot

Two halves of one project: a machine learning pipeline that predicts peripheral artery disease (PAD) from routine hospital data, and a RAG copilot that turns each prediction into an explanation a reader can check.

Role
solo or team? confirm
Stack
Python, scikit-learn, XGBoost, LightGBM, SHAP, Ollama, Streamlit
Links
GitHub

Problem

The pipeline predicts PAD from data a hospital already collects: labs, demographics, comorbidities and medications. But a prediction on its own is of little use to a reader who can't check it. The copilot answers why this score? with SHAP attributions and cited passages from public clinical references.

Users

Researchers and clinicians reviewing a risk score, for research use only. This is not a medical device and has not been validated prospectively or externally.

confirm the intended user and whether anyone outside the project has used it.

Constraints

  • Data use agreement. MIMIC-IV values cannot be sent to a third party under the PhysioNet agreement, so the language model runs locally through Ollama and no API is used.
  • Hardware. Both models (llama3.1:8b and nomic-embed-text) have to fit together on an 8 GB GPU.
  • Noisy label. The label is a billing code, not a diagnosis, and MIMIC-IV is an ICU population, sicker than the general public.
  • Missing signals. There is no ankle-brachial index, no smoking status and no imaging in these tables.

What I built

The model. A matched case-control cohort from MIMIC-IV, 13 engineered features (demographics, labs, comorbidities, medications) and six classifiers: logistic regression, random forest, SVM, MLP, XGBoost and LightGBM. The winner is chosen by grouped 5-fold cross-validation and scored once on a held-out test set.

Leakage controls, each covered by a test that was checked to fail against the earlier behaviour:

  • Patient-level cohort and split, so no one appears as both a case and a control, or in both train and test.
  • Comorbidities and medications come only from strictly earlier admissions. Statins are the standard PAD treatment, so counting them from the index stay would leak the diagnosis.
  • Controls matched 1:1 on age bracket × gender, so the model has to learn something clinical.
  • Drug names are matched exactly, not by substring (a bare statin pattern also matches nystatin, an antifungal).

The copilot. It scores the record, computes SHAP attributions, retrieves passages from an index of NHLBI and CDC pages plus a model card, asks a local LLM to explain citing those passages, then verifies every citation in code. Any [n] that doesn't resolve to a retrieved passage is stripped and flagged. There's a Streamlit UI on top.

Trade-offs I made

  • A local 8B model instead of a stronger hosted one.The answers are weaker, but it's the only option the data agreement allows. The weaker model is also exactly why citation checking has to live in code.
  • The copilot refuses rather than improvises.If no passage clears the relevance threshold, the LLM is never called and the copilot says so.
  • No silent fallback embedder.An offline hashing embedder exists for tests but must be requested by name. It scores 0.79 / 0.54 (hit@6 / hit@1) against 1.00 / 0.79 for real embeddings, and a quiet fallback would hide that gap.
  • Wording SHAP as score movement, not causation.Given "statin therapy increases", the model once wrote that statins increase PAD risk. Factors are now phrased as "pushed the score up/down".
  • Only prior admissions for comorbidities and medications.This gives up some signal to avoid leaking the diagnosis into the features.

What I'd do next

  • Calibrate the probabilities (Platt or isotonic). Matched controls change the base rate, so today's output is a discrimination score, not a probability.
  • Rerank retrieved passages before generation.
  • Add features from MIMIC-IV-Note clinical notes, such as smoking status and mentions of claudication.
