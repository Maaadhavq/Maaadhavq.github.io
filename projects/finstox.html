Finstox

The backend for Finstox, a stock-trading demo website built for a Web Programming course. It is not a real trading platform. It serves LSTM price predictions for NSE stocks with a LIME and SHAP explanation for every prediction.

Role
Backend confirm team size and who built the frontend
Stack
Python, FastAPI, TensorFlow/Keras, LIME, SHAP, JWT auth
Links
GitHub

Problem

A predicted price on its own gives a non-technical user no way to judge whether to trust it, or what the prediction is based on.

Users

Non-technical users of the Finstox demo site who want to understand a prediction before acting on it. confirm the intended user and whether anyone outside the course used it.

Constraints

  • A course project, built as a demo and not a regulated trading service.
  • Only free public market data, fetched through yfinance and nsepython.
  • add other constraints (deadline, compute, team).

What I built

  • A FastAPI service with JWT authentication, NSE market status, stock search suggestions and company logos.
  • An LSTM model (TensorFlow/Keras) trained on recent price history for NSE stocks.
  • LIME and SHAP explanations for each prediction, so users can see which inputs moved the forecast.

Metrics

add a measured result, such as prediction error on held-out days or what users did with the explanations.

Trade-offs I made

  • Explanations for each prediction, not global feature importance.The user's question is about the stock in front of them, not the model in general.
  • Both LIME and SHAP.explain why both, e.g. whether they agreed and which one users found clearer.
